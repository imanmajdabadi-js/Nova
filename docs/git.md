# Git

## Convention

Use Conventional Commits.

## Allowed Prefixes

- `feat` — a new feature
- `fix` — a bug fix
- `refactor` — code structure changes without behavior change
- `chore` — maintenance, tooling, config
- `test` — tests
- `docs` — documentation
- `perf` — performance improvements

## Message Style

- Short, focused, human-readable.
- Imperative mood: "add", not "added" / "adds".

## Examples

- `feat: add experience discovery`
- `fix: correct booking form validation`
- `refactor: simplify experience card`
- `docs: update architecture notes`

## Avoid

- Vague commits (`update`, `changes`, `fix stuff`)
- Huge, multi-purpose commit messages
- Artificial micro-commits
- `final`, `final-final`, `changes`, `update everything`

## Guidance

- Stage intentionally; avoid committing unrelated noise.
- One logical change per commit where practical.
- Do not amend published commits.
